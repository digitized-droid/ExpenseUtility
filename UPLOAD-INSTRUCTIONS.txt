PESOPLAN — TRANSACTION-SAFE OFFLINE/CLOUD SYNC UPDATE

THIS UPDATE
- Keeps Supabase as the authoritative starting point when the cloud row exists.
- Merges locally stored transactions that are missing from the cloud by transaction ID.
- Starts balance reconciliation from the cloud balances and applies only the balance effect of locally missing transactions. It does not add two devices' complete balances together.
- Reads the latest cloud row before each upload, then writes the merged transaction list.
- Retries synchronization when the device comes back online.
- Bumps the service-worker cache name so the browser replaces the old app shell after deployment.

BEFORE UPLOADING
1. Do not clear browser/site data or uninstall the app.
2. While online, export a PesoPlan backup if the app's export feature is available.
3. Keep a copy of the current GitHub repository ZIP and your existing icons/ folder.
4. If you have important offline-only transactions on another device, do not sign that device in and sync it until you have exported a backup. This update merges locally present transactions, but the app cannot recover records that have already been erased from browser storage.

UPLOAD
1. Open https://github.com/digitized-droid/practicemedaddy
2. Upload/replace the files inside this folder at the repository root: index.html, service-worker.js, manifest.webmanifest, supabase-config.js, README.md, and UPLOAD-INSTRUCTIONS.txt.
3. Do not delete any existing icons/ folder or other repository assets.
4. Commit the changes to the branch used by GitHub Pages (usually main).
5. Wait for GitHub Pages to deploy, then open https://digitized-droid.github.io/practicemedaddy/ while online.
6. Refresh once. The service worker uses a new cache version and should replace the previous app shell. If an installed PWA still shows the old version, close it fully and reopen it while online; if needed, clear only that site's cached files after confirming your data backup is safe. Do not clear site storage.

TESTING THE SYNC
1. On the device with the cloud data, open the app online and sign in. Confirm the expected cloud transactions are visible.
2. Add one clearly identifiable test transaction while online and confirm it appears on another device after sync.
3. On one device, go offline and add a different test transaction. Confirm it remains visible after refreshing/reopening the app offline.
4. Reconnect that device to the internet. Wait for the status to report that it synced, then check the other device for the transaction.
5. Confirm the transaction appears exactly once on both devices and balances reflect the transaction once.
6. Delete test transactions only after confirming sync on both devices.

IMPORTANT LIMITATIONS
- This patch prioritizes adding/preserving transactions. It merges remote and local transaction records by ID. It does not yet implement deletion tombstones or conflict resolution for editing an existing transaction. A transaction deleted offline may reappear when merged with the cloud; resolve such deletions while online on the device that has the latest cloud state.
- Non-transaction data (wishes, bills, settings, categories) continues to use the cloud record as the source of truth when a cloud row already exists. This update is not a complete multi-device merge for those sections.
- The database still stores the app state as one JSON row. Reading the latest row before writing reduces stale overwrites, but it is not a fully atomic transaction log; simultaneous edits from two devices at exactly the same time can still race.
- Keep regular exports. Browser storage is device/browser-specific and can be erased by clearing site data or uninstalling the app.
- Cloud sign-in/sync requires internet. The app shell and localStorage data can work offline after the app has been opened online once.
